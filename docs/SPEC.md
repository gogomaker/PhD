## 0. 한 문단 요약

PhD는 **목표를 이루기 위한 계획**을 세우는 웹 다이어리다. 잘 만든 종이 스터디 플래너를 웹으로 옮긴 것. 사용자는 데스크톱에서 목표를 세우고 연간 → 월간 → 주간 계획 표로 쪼개 내려오며, 주간 표에 적은 "실천"이 모바일 하루 플래너의 할 일이 된다. 모바일에서는 할 일을 체크하고 10분 단위 시간표를 형광펜처럼 칠해 기록하며, 그 기록이 데스크톱 트래킹으로 다시 올라간다.

**타깃**: 목표를 이루려는 사람. "그냥 오늘 할 일만 적고 싶은" 사용자는 타깃이 아니다. 기능을 넣고 뺄 때 이 기준으로 판단한다.

## 1. 용어 (코드·UI 모두 이 이름으로 통일)

| 용어 | 영문 식별자 | 설명 | 예 |
|---|---|---|---|
| 궁극적 꿈 | `dream` | 한 문장. **선택 사항** | 배운 것을 나누며 사는 연구자 |
| 카테고리 | `category` | 삶의 영역. 7색 중 1색 | 건강, 어학, 일상 |
| ├ 목표 카테고리 | `kind = 'goal'` | 목표를 세우는 영역. 최대 6개 | 어학 |
| └ 일상 카테고리 | `kind = 'daily'` | 목표 없이 생활·시간 기록용. **정확히 1개** | 일상 |
| 일상 키워드 | `daily_keyword` | 일상 카테고리 안의 하위 분류 | 업무, 생활, 이동, 휴식 |
| 되고 싶은 모습 | `category.aspiration` | 카테고리별 한 문장 (유지하는 것이 기획 의도) | 매일 30분, 몸을 움직이는 사람 |
| 목표 | `goal` | 목표 카테고리에 속함. 계획 표의 **열** | 토익 850 |
| 세부목표 | `subgoal` | 목표 아래 단위. 꿈 보드에서 만듦 | 단어, LC, RC |
| 실천 | `practice` | 주간 표에 적는 구체적 행동. 세부목표 1개에 속함 | 매일 단어 40개, LC 교재 2장 |
| 할 일 | `task` | 실천이 하루에 실행된 것, 또는 모바일에서 직접 적은 일 | 10/1의 "매일 단어 40개" |
| 계획 블록 | `time_block (layer=plan)` | 모바일 시간표의 회색 테두리 구간 | 15:00–16:00 치과 |
| 실제 블록 | `time_block (layer=actual)` | 모바일 시간표의 형광펜 구간 | 09:00–10:00 LC |
| 하루 기록 | `day_journal` | 점수(1~5)·이유 한 줄·감사 3줄·메모 | |
| 참고사항 | `note` | 월간·주간 표의 회색 메모 열. 모바일로 내려가지 않음 | 개천절 연휴 |

구조 (기획 중 "나무" 비유: 뿌리=꿈, branch=목표, twig=세부목표, leaf=실천):

```
궁극적 꿈 (선택)
└ 목표 카테고리 (≤6)          + 일상 카테고리 (1) ─ 일상 키워드들
  └ 목표                        └ (목표 없음, 모바일 직접 추가·시간 칠하기 전용)
    └ 세부목표
      └ 실천 (주간 표)
        └ 할 일 (모바일, 하루 단위)
```

## 2. 기술 방향

| 항목 | 결정 | 상태 |
|---|---|---|
| 앱 형태 | **하나의 반응형 웹앱.** 넓은 화면 = 데스크톱 레이아웃(계획), 좁은 화면 = 모바일 앱(계획 + 기록, 2026-10-02 모바일 통합) | 확정 |
| 백엔드 | **BaaS 사용** (서버 직접 구현 안 함) | 확정 |
| BaaS 종류 | 데이터가 강하게 관계형(목표→세부목표→실천→할 일)이고, 로그인·파일 저장(인증사진)·행 단위 권한이 필요하므로 **Supabase(Postgres) 권장** | **결정 필요** — 첫 작업 전에 Claude Code가 근거와 함께 제안하고 기획자가 승인 |
| 프레임워크 | Claude Code가 제안 (반응형 + PWA + BaaS 연동이 쉬운 것) | 결정 필요 |
| PWA | 필요. 예약 할 일 **알람(웹 푸시)** 때문 | 확정 |
| 시간대 | 기본 `Asia/Seoul`. 모든 "날짜" 계산은 사용자 시간대 + 하루 시작 시각 기준 | 확정 |

### 2.1 반응형 기준
- 데스크톱 레이아웃: 사이드바 + 본문. 목표 작성·계획 표·트래킹·회고 모음.
- 모바일 레이아웃(손가락 기기: 폭 768px 미만 또는 짧은 변 768px 미만 /  마우스 기기(PC): 창 폭 600px 미만, 2026-10-03 UT. PC 창이 1000px보다 좁으면 사이드바는 아이콘만): **휴대폰만으로 전부 쓸 수 있는 앱** (2026-10-02 기획 결정, `docs/MOBILE.md`). 휴대폰은 **세로로만** 쓴다 — 가로로 돌리면 화면을 덮는 '휴대폰을 세로로 돌려 주세요' 안내(쓰던 내용은 그대로), 설치한 앱은 세로로 고정 (2026-10-03 UT 3차 기획 결정, 이전: 가로에서도 휴대폰 화면). 앱바의 '계획 | 기록' 전환 — 계획 = 목표·일정(연간·월간·주간), 기록 = 오늘(하루 플래너)·돌아보기. 생김새는 목업 `PhD only for Mobile v2`, 기능은 데스크톱과 같은 규칙.
- 데스크톱 화면은 그대로 둔다(넓은 화면). 같은 계정, 같은 데이터, 같은 DB 규칙.

### 2.2 알람 제약 (검수 시 참고)
- 웹 푸시는 PWA 설치가 필요하다. **iPhone은 홈 화면에 추가한 경우에만** 받을 수 있다(iOS 16.4+).
- 기획자는 iPhone이 없으므로 iOS 알람은 직접 검수할 수 없다. Android 크롬 기준으로 검수한다.

## 3. 데이터 모델 (초안)

Claude Code가 BaaS에 맞게 다듬되, **아래 관계와 제약은 유지**한다. 모든 테이블은 `user_id` 기준 행 단위 권한(본인만 읽기·쓰기).

### 3.1 사용자·설정
**profiles**
- `name`, `life_stage` (대학생 / 수험생 / 직장인 / 군 복무 중 / 그 외) — 카테고리 추천에 사용
- `dream` (nullable), `dream_why` (nullable), `dream_day` (nullable)
- `day_start_hour` (4 / 5 / 6, 기본 5) — 하루의 경계
- `week_start` — **일요일 고정** (2026-10-01 기획 결정. 사용자가 바꿀 수 없다)
- `review_notify_enabled`, `review_notify_time` (기본 22:00)
- `timezone` (기본 Asia/Seoul)

### 3.2 카테고리
**categories**
- `kind`: `goal` | `daily`
- `name`, `color` ∈ {red, orange, yellow, green, blue, purple, pink}
- `aspiration` (되고 싶은 모습, nullable, goal 카테고리만)
- `position`
- 제약: 사용자당 `color` 중복 불가 / `kind='goal'` 최대 6개 / `kind='daily'` 정확히 1개(가입 시 자동 생성, 삭제 불가, 이름·색 변경 가능)
- 목표 카테고리 `color`는 사용자가 고르지 않는다. `position` 순서대로 빨강→주황→노랑→초록→파랑→보라→분홍에서 일상 색을 건너뛰고 자동으로 매긴다(DB 트리거)

**daily_keywords**
- `category_id`(daily), `name`, `position`
- 기본값: 업무, 생활, 이동, 휴식 (추가·삭제 가능)

### 3.3 목표
**goals**
- `category_id` (goal 카테고리만), `name`, `position`
- 특성: `due_month` (필수 — 목표를 적을 때 바로 받는다, 2026-10-01 기획 결정), `reason`, `importance` (high / mid / low), `fallback` (대안) — reason·importance·fallback은 선택
- `status`: `not_started` | `in_progress` | `completed` | `dropped`
- `started_at` — 이 목표의 실천이 처음 주간 표에 배치된 시각
- 마무리: `finished_at`, `finish_photo_path`(완성일 때만), `retro_achieved`, `retro_regret`, `retro_next`
- `table_position`, `table_hidden` — 계획 표 열 순서·숨김

**subgoals**
- `goal_id`, `name`, `position`

**goal_progress**
- `goal_id`, `percent` (0~100), `updated_at` — 사용자가 트래킹 화면 슬라이더로 직접 매김. 변경 이력 보관 권장

### 3.4 계획 표
**year_cells** — 연간 표
- `goal_id`, `subgoal_id`, `start_month`, `end_month` (병합 범위), `memo`
- `extra_subgoal_ids` — 같은 칸의 나머지 세부목표 (`subgoal_id` = 첫 것, R-P17)

**month_cells** — 월간 표
- `goal_id`, `subgoal_id`, `year_month`, `start_week`, `end_week` (병합), `comment`
- `extra_subgoal_ids` — 같은 칸의 나머지 세부목표 (R-P17)

**notes** — 참고사항 열 (월간·주간 공통)
- `scope` (`month` | `week`), `period_key`, `start_index`, `end_index` (병합), `text`

**practices** — 실천 (주간 표)
- `goal_id`, `subgoal_id`, `week_start_date`, `name`
- `kind`: `repeat` | `once` — 사용자가 고르지 않는다. **요일 1개 = once, 2개 이상 = repeat** (2026-10-01 기획 결정: 단발/반복 고르기 없앰)
- `weekdays`: 요일 집합 (1개 이상)
- 표시 위치: 요일이 **1개**면 그 요일 칸, **2개 이상**이면 "이번 주" 줄

### 3.5 하루
**tasks** — 할 일 (하루 인스턴스)
- `date` (사용자 기준 날짜), `source`: `repeat` | `auto` | `picked` | `direct`
- `practice_id` (direct 아니면 필수)
- direct 전용: `name`, `daily_keyword_id`
- 예약: `is_timed`, `start_time`, `end_time`, `alarm`
- `done_at`, `carried_from_date`
- `list_number` 는 저장하지 않고 화면에서 계산 (4.5 참조)

**time_blocks**
- `date`, `layer`: `plan` | `actual`
- `start_slot`, `end_slot` — 0~143 (하루 시작 시각 기준 10분 단위, 끝 포함). **구간 단위로 저장**
- 연결 대상 (하나): `task_id` | `daily_keyword_id` | `label`(자유 키워드, plan만) | 없음(plan의 이름 없는 블록)
- 같은 날·같은 층에서 구간은 겹치지 않는다 (칠할 때 덮어쓰기)

**day_journals**
- `date`, `score` (1~5), `reason` (한 줄), `thanks` (3줄), `memo`

> 할 일을 미리 만들어 둘지(materialize) 그날 열 때 계산할지는 Claude Code가 정한다. 단, **4장의 동작 규칙과 결과가 같아야 한다.**

## 4. 동작 규칙

검수 때 규칙 번호로 지적할 수 있도록 번호를 붙였다.

### 4.1 카테고리·목표
- **R-C1** 목표 카테고리 최대 6개 + 일상 1개 = 최대 7색, 색은 겹치지 않는다. 일상 카테고리 색만 직접 고르고, 목표 카테고리 색은 **순서대로** 정해진다(빨강→주황→노랑→초록→파랑→보라→분홍, 일상 색은 건너뜀). 순서를 바꾸거나 지우면 색도 따라 바뀐다. (2026-10-01 기획 결정)
- **R-C2** 일상 카테고리는 목표 설정·꿈 보드·계획 표에 **나타나지 않는다.**
- **R-C3** 목표는 카테고리 1개에만 속한다. 색은 카테고리 색을 따른다.
- **R-C4** 목표가 들어 있는 카테고리는 지울 수 없다. 목표를 다른 카테고리로 옮기거나 지운 뒤 지운다. (2026-10-01 기획 결정)
- **R-C5** 가입 3단계는 고른 시기의 **카테고리 템플릿을 미리 골라 둔다**. 바탕은 '삶의 수레바퀴(Wheel of Life)'의 영역(건강·일/학업·재정·관계·성장·여가)을 시기에 맞게 이름 붙인 최대 6개. 사용자가 빼거나 더할 수 있다 (2026-10-03 기획 결정, `src/lib/lifeStage.ts`)
- **R-C6** 일상 카테고리의 키워드는 **최대 6개**(지운 키워드는 세지 않음). 6개면 추가 칸 대신 "최대 6개예요. 하나를 지우면 새로 추가할 수 있어요". 지운 키워드를 되살릴 때도 같음. 서버(DB)도 막는다 (2026-10-05 기획 요청)
- **R-G1** 세부목표는 반드시 목표 1개에 속한다.
- **R-G2** 세부목표가 0개인 목표는 계획 표 열로 추가할 수 없다. 새 목표는 처음부터 표에 올린 상태다 — 세부목표가 생기면 바로 열로 보인다 (2026-10-03 UT 8, 이전: '+ 목표 열'로 올려야 함). (안내: "꿈 보드에서 세부목표를 먼저 추가해 주세요")
- **R-G10** (데스크톱) 표에 올리지 않았거나 숨긴 목표라도 **보고 있는 기간에 계획(연간 칸·월간 칸·이번 주 실천)이 있으면** 열로 보인다. 이 열에는 '표 밖' 표시, ‹ › ×는 없고 '+ 목표 열'에서 올릴 수 있다. 휴대폰엔 열 개념이 없어 휴대폰에서 넣은 계획이 PC 표에서 사라지지 않게 (2026-10-03 기획 결정)
- **R-G3** 목표의 "시작" = 그 목표의 실천이 **주간 표에 처음 배치된 시점.** 그때 `not_started → in_progress`. 실천을 모두 지우면 다시 `not_started`로 돌아간다(단, 할 일을 체크했거나 시간을 칠한 기록이 있으면 되돌리지 않는다). (2026-10-01 기획 결정)
- **R-G4** `not_started` 목표만 **삭제** 가능. 삭제 시 연간·월간 칸도 함께 지워진다는 확인을 받는다.
- **R-G5** `in_progress` 목표는 삭제 불가, **마무리**만 가능.
- **R-G6** 마무리 종류는 **완성 / 중도 마무리**. 완성일 때만 인증사진 1장(선택, 본인만 볼 수 있는 비공개 저장소). 회고 3칸(해낸 것, 아쉬운 점, 다음에 다르게 할 것). 기간·누적 시간·완료 실천 수는 자동 요약.
- **R-G7** 마무리한 목표는 **다시 열 수 없다.** 같은 일을 다시 하려면 새 목표를 만든다.
- **R-G8** 마무리한 목표는 꿈 보드에서 흐리게 + 배지로 카테고리 맨 아래, 계획 표 열에서는 빠진다. 과거 기록·트래킹 집계는 유지. 그 목표의 실천은 **마무리한 다음 날부터** 모바일 할 일로 나오지 않는다(넘어오던 일 포함, 2026-10-01 기획 결정).
- **R-G9** 세부목표 이름을 바꾸면 계획 표의 칩에도 반영된다. 계획 표에 배치된 세부목표는 삭제 불가("계획 표에 배치됨") — 칸의 나머지 자리(R-P17)에 든 것도.

### 4.2 계획 표 3종
| 표 | 행 | 칸 내용 | 역할 |
|---|---|---|---|
| 연간 | 월 (1월~12월 달력 연도, 앞뒤 해로 이동 — 2026-10-01 기획 결정) | 세부목표 + 짧은 메모 | 큰 배치 |
| 월간 | 주차 | 세부목표 + 코멘트 | 이번 달 사정에 맞춘 재배분 |
| 주간 | "이번 주" 줄 + 요일 7줄 | 실천 여러 개 | 실제 실천 작성 |

- **R-P1** 모든 표의 열 = 목표. 열 하나는 **항상 세로 한 줄**(열 쪼개기·레인 금지). 한 기간·한 목표에 **칸은 하나** — 칸 안의 세부목표는 여러 개일 수 있다(R-P17).
- **R-P2** 연간·월간 칸은 병합으로 기간을 표현한다.
- **R-P3** 월간·주간 표 맨 위에 **"상위 계획" 줄**: 월간에는 연간의 이번 달 칸이, 주간에는 월간의 이번 주 칸이 읽기 전용으로 내려온다.
- **R-P4** 월간에서 바꾼 내용은 연간에 **반영되지 않는다.** 연간은 "처음 계획"으로 남는다.
- **R-P5** 월간 칸 팝오버: 그 목표의 세부목표 전체를 보여주되, 연간 표에서 이번 달에 배치한 세부목표(칸에 여러 개면 모두)를 맨 위에 "이번 달 계획"으로 강조.
- **R-P6** 주간 표에는 **칸 병합이 없다**(참고사항 열 제외). 요일 칸에는 하루짜리 실천만 위아래로 쌓는다.
- **R-P7** 실천 추가 팝오버: 세부목표 선택(상위 계획 줄의 세부목표 강조) → 이름 → 요일 칩(복수 선택). 요일 칸을 눌러 열면 그 요일이 미리 선택됨. 단발/반복은 요일 수로 정해진다 (2026-10-01 기획 결정: 단발/반복 고르기 없앰). **시간(선택)**: 시작~끝(10분 단위)을 정하면 고른 요일마다 그날 시간표에 예약처럼 계획 칸이 놓이고 그 시각에 알람이 울린다. 일정에 시간이 함께 보이고, 트래킹에서는 그 목표의 계획 시간으로 센다 (2026-10-03 UT 5).
- **R-P8** 요일 1개 → 그 요일 칸. 2개 이상 → "이번 주" 줄, 오른쪽에 요일 표시: 연속 "수–금", 떨어짐 "월·수·금", 전체 "매일". 반복 실천은 ↻ 아이콘.
- **R-P9** 칸 안 실천이 3개를 넘으면 "+N개 더"로 접는다.
- **R-P10** 참고사항 열(월간·주간)은 자유 메모. 모바일로 내려가지 않는다.
- **R-P11** 반복이라는 개념은 **실천에만** 있다. 세부목표·목표에는 반복 속성이 없다.
- **R-P12** 지난 기간의 계획은 **무조건 잠근다** — UI와 서버(DB 권한) 모두 (R-D2와 같은 원칙). 연간 칸은 지난달에 걸치면, 월간 칸·월간 참고사항은 지난주에 걸치면, 주간 참고사항·실천은 지난 날이 하나라도 들어가면 추가·수정·삭제 불가. 이번 주 실천을 추가할 때도 지난 요일은 고를 수 없다. (2026-10-01 기획 결정)
- **R-P13** 한 주는 **일요일**에 시작한다. 두 달에 걸친 주는 날이 더 많은 달(그 주 수요일이 있는 달)의 주로 친다.
- **R-P14** 아래 계획은 **위 계획에서 먼저 고른다**: 월간 칸은 그 달 연간 계획의 세부 목표, 주간 실천은 그 주 월간 계획의 세부 목표가 먼저 보이고, 그 밖은 '계획 밖에서 추가(고르기)'를 한 번 더 눌러야 한다. 위 계획에 없는 항목은 일정·계획 표에 '계획 밖'으로 표시(칸의 세부목표 중 하나라도 없으면 그 칸). 위 계획이 비어 있으면 모든 목표에서 고른다(연간은 선택). 데스크톱 팝오버(R-P5, R-P7)도 같다 — 그 목표가 위 계획에 없으면 안내 후 모두 '계획 밖'. (2026-10-03 기획 결정, 데스크톱 적용도 같은 날)
- **R-P16** (PC 표) 빈 칸을 **끌어서** 이어진 빈 칸 여러 개를 한 번에 고르면 그 기간으로 넣기 창이 뜬다. 고른 칸은 **Delete**로 지우고, 안내의 '되돌리기'나 **Ctrl+Z(⌘Z)**로 방금 지운 것을 살린다(실천도 같음). 되돌리기는 지운 화면 안에서만 — 다른 화면으로 옮기면 없어진다. 늘리기·줄이기는 서버 답을 기다리지 않고 바로 화면에 — 빠르게 여러 번 눌러도 빠지지 않는다 (2026-10-03 UT 11·14)
- **R-P17** 연간·월간 **칸 하나에 세부목표를 여러 개** 넣을 수 있다 (예: '신앙 매일 지키기' — 기도 · 성경 · 묵상을 1년 내내 함께). 같은 목표의 세부목표만, 겹치지 않게, 한 칸에 최대 11개(DB가 막음). 칸에는 '기도 · 성경 · 묵상'처럼 이어 보인다. PC: 칸을 고르면 칩마다 ×(하나는 남김)와 '+ 세부목표'(남은 것만, 월간은 연간의 이번 달 것을 먼저). 휴대폰: '+ 계획'에서 같은 목표의 세부 목표를 여러 개 골라(위 계획 칩도 같은 목표면 함께 골라짐) 한 칸으로, 칸 고치기 시트에서 세부 목표를 더하고 뺀다. 지난 칸은 그대로 잠금(R-P12). 실천(주간)은 그대로 세부목표 하나 (2026-10-05 기획 결정)
- **R-P18** **지난주 실천 가져오기**: 반복은 한 주 안에서만(R-P11, 요일 2개 이상 = 그 주의 고른 요일마다). 주가 바뀌면 이어지지 않으므로, 주간 화면(휴대폰 일정 › 주간, PC 주간 계획)에 '지난주 실천 N개 가져오기'를 둔다. 누르면 앞 주 실천 목록(기본 모두 고름)에서 고르고, 요일도 고쳐서 넣는다(주 중간에 넣어 '수–토'였던 것을 다음 주엔 '매일'로). 지난 요일은 빼고(R-P12), 남는 요일이 없거나 마무리한 목표, 이번 주에 같은 실천(목표·세부목표·이름)이 이미 있으면 목록에 없다. 시간·알람도 그대로. 지난주 화면에는 버튼이 없다 (2026-10-06 기획 결정)
- **R-P15** (모바일) 계획 칸·참고사항의 기간은 시작·끝 드롭다운으로 고르고, **달(월간)·해(연간)를 넘으면 달·해마다 나눠 저장**한다. 나눠진 칸은 따로 고치고 지울 수 있다. 여러 기간에 걸친 칸은 걸친 줄마다 보인다(첫 줄 = 기간, 다음 줄 = '이어짐'). 빈 칸을 눌러 바로 넣지 않고 '+ 계획 / + 실천'으로만 넣는다. 한 기간·한 목표에 칸은 하나(R-P1) — 세부 목표는 한 칸에 여러 개(R-P17). 데스크톱 표는 그대로 빈 칸 클릭으로 넣고, 늘리기(↓)는 그 달(월간)·그 해(연간) 안에서만 — 휴대폰에서 나눠 저장한 칸은 달·해마다 따로 보인다. (2026-10-03 기획 결정)

### 4.3 모바일 — 할 일이 생기는 방법
| 섹션 | 출처 | 들어오는 방식 | 못 했을 때 |
|---|---|---|---|
| 반복 | `repeat` | 요일이 2개 이상인 실천 중 **오늘 요일이 포함된 것**이 자동으로 | 넘어가지 않음(기록에 미완료로 남음) |
| 오늘 할 일 | `auto` | 단발 실천 중 요일이 **오늘 하나뿐인 것**이 자동 배정 | **다음 날로 넘어감** ("어제에서" 표시) |
| 오늘 할 일 | `direct` | 모바일에서 직접 추가 (일상 키워드 선택) | **다음 날로 넘어감** |
| 오늘 할 일 | `direct` + 예약 | 직접 추가 시 "시간 지정" 켬 | **넘어가지 않음** |

- ~~R-T1, R-T2~~ ("이번 주에서 담기"·기간 단발 실천은 없앰. 여러 요일 실천은 고른 요일마다 하는 반복 (2026-10-01 기획 결정: 단발/반복 고르기 없앰))
- **R-T3** 예약 할 일은 시작·끝 시각(10분 단위)을 받고 — 끝은 **하루 시작 시각 기준**으로 시작보다 뒤면 된다: 5시 시작이면 23:00~01:00도 되고, 04:00~06:00처럼 하루를 넘는 것은 안 된다(실천 시간도 같음, 2026-10-03 UT 3차) — 시간표 계획 층에 **자동으로 회색 블록**이 생기며(알람 아이콘), 시각에 맞춰 알람.
- **R-T4** 할 일 태그: 목표에서 온 것은 **세부목표 이름**, 직접 추가는 **"일상 · 키워드"**. 색은 카테고리 색.
- **R-T5** 직접 추가는 '일상 키워드' 대신 **진행 중 목표의 세부목표**에 연결할 수 있다. 태그·색은 실천과 같고, 칠한 시간·완료가 그 목표의 트래킹·누적에 쌓인다. 연결한 할 일을 만들면 그 목표는 '진행 중'이 되고, 기록에 쓰인 세부목표는 지울 수 없다 — 삭제 버튼이 꺼지고 '할 일 기록에 쓰임'으로 보인다 (2026-10-03 UT 9, UT 2차).
- **R-T5** "다음 날로 넘어가는" 할 일은 **끝낼 때까지 매일 넘어간다**. 하루 지난 것은 "어제에서", 더 오래된 것은 "9.28에서"처럼 처음 날짜를 보여준다. 지난 날 기록에는 미완료로 남는다. (2026-10-01 기획 결정) 단, 목표에 연결한 직접 추가는 그 목표를 마무리하면 더는 넘어가지 않는다 (2026-10-03 UT 2차).
- 오늘 할 일 목록과 일정의 실천은 **시각 순**(시간을 정한 것 먼저, 시간 없는 것은 뒤)으로 보인다 (2026-10-03 UT 2차)
- **R-T6** 오늘·내일 **직접 추가한** 할 일은 길게 눌러(메뉴의 '지우기') 지울 수 있다. 주간 표에서 온 할 일은 주간 표에서만 지운다. (2026-10-01 기획 결정)
- **R-T7** 할 일 **취소**(완료와 따로): 더 안 하기로 한 일은 길게 눌러 '할 일 취소'. 그날 목록에 ×와 줄을 그어 '취소함'으로 남고(완료 ✓와 다른 표시), 다음 날부터 넘어오지 않는다. 개수(완료 / 할 일)에서 빠지고, 알람도 울리지 않는다. 취소·풀기는 체크처럼 **오늘만** (R-D2). 길게 누르면 메뉴: 취소 · (오늘·내일 직접 추가한 것은) 지우기 (2026-10-03 UT 4차 기획 결정)

### 4.4 모바일 — 날짜별 권한 (가장 중요한 원칙: 지난 날은 손댈 수 없다)
| | 오늘 | 내일 | 모레 이후 | 지난 날 |
|---|---|---|---|---|
| 할 일 체크 | O | X | X | X |
| 담기·직접 추가 | O | O | X | X |
| 계획 블록 그리기 | O | O | X | X |
| 실제 칠하기 | O | X | X | X |
| 하루 기록 작성 | O | X | X | X |
| 보기 | O | O | 배정된 실천만 흐리게 | 읽기 전용 |

- **R-D1** "오늘"은 사용자 시간대 + `day_start_hour` 기준. 05시 시작이면 새벽 1시는 아직 전날이다.
  - 하루 시작 시각을 바꾸면 **칠한 기록은 실제 시각 그대로** 남고 하루의 경계만 바뀐다 — 경계 근처 기록은 앞날·다음 날로 옮겨질 수 있다. 바꾸면 '오늘'이 어제로 돌아가는 경우(예: 새벽 5시 반에 5시 → 6시)는 지난 날이 다시 열리므로 그 시각이 지난 뒤에만 바꿀 수 있다 (R-D2) (2026-10-03 UT 3차 기획 결정)
- **R-D2** 지난 날 잠금은 **UI만이 아니라 서버(권한 규칙/DB 제약)에서도** 막는다. 이 서비스의 핵심 가치가 "얼마나 성실했는지 정직하게 보이는 것"이기 때문.
- **R-D3** 날짜 이동: 날짜 탭 → 달력 / 좌우 화살표 / **시간표 밖 어디서나** 좌우로 밀기(시간표 위는 칠하기라 제외, 지류처럼 왼쪽으로 밀면 다음 날) / 오늘이 아닐 때 "오늘" 버튼. 일정(연간·월간·주간)과 돌아보기도 밀어서 이전·다음 기간 (2026-10-03 UT 6, 이전: 날짜 줄에서만).

### 4.5 모바일 — 10분 시간표
- **R-S1** 한 줄 = 1시간, 6칸 = 10분씩. `day_start_hour`부터 24시간.
- **R-S2** 격자는 얇은 선, 칸 사이 틈 없음. 30분 위치에 점선.
- **R-S3** 두 층:
  - **계획**: 회색 테두리 네모(안은 거의 투명). 이름은 안쪽 왼쪽에 작게. 20분 이하 구간은 이름 생략.
  - **실제**: 카테고리 색 반투명 형광펜 띠(칸 높이 약 70%). 계획 테두리 **아래** 층.
- **R-S4** 블록은 칸이 아니라 **구간**으로 그린다(한 시간 줄 안 연속 구간 = 도형 하나, 여러 줄이면 줄마다 하나, 이름·번호는 첫 줄에만).
- **R-S5** 칠하기는 **형광펜 방식**: 누른 칸부터 현재 칸까지 시간순 구간 전체. 되돌아가면 구간이 줄고 벗어난 칸은 드래그 시작 전 상태로 복원(스냅샷). 거꾸로 긋기 지원. 이미 칠한 칸에서 시작하면 지우기.
- **R-S6** 계획 그리기: 드래그 후 시트에서 **할 일 선택 / 키워드 입력(일상 키워드 칩 제시) / 건너뛰기(이름 없음)**. 블록을 누르면 이름 변경·삭제. 할 일과 연결된 계획은 이름 앞에 카테고리 색 점. 계획 그리기 시 예약 블록 칸은 건너뛴다.
- **R-S7** 실제 칠하기: 할 일 하나 또는 일상 키워드 하나를 브러시로 고르고 칠한다. 다른 것으로 칠해진 칸은 덮어쓴다.
- **R-S11** 오늘의 실제 시간은 **지금 칸까지만** 칠한다. 그 뒤 칸은 흐리게 보이고, 거기서 시작하면 "아직 오지 않은 시간은 칠할 수 없어요". 서버(DB)도 지금 칸 + 1칸(기기 시계 여유)까지만 받는다 (2026-10-03 UT) 그 칸을 누르면 아래 안내 "아직 오지 않은 시간은 칠할 수 없어요. 앞으로 할 일은 '계획 그리기'로 그려요"와 바로 바꾸는 '계획 그리기' 버튼 (2026-10-04 기획 요청)
- **R-S13** 할 일·키워드를 안 고른 채 칠하면 손을 뗄 때 **"무엇을 했나요?"** 시트가 뜬다(오늘 할 일 + 일상 키워드). 고르면 그 색으로 저장되고 이어서 칠할 붓이 된다. '칠하지 않기'면 되돌린다 (2026-10-03 UT 10)
- **R-S12** 연결이 끊겨 시간표를 못 보내면 화면은 그대로 두고 이 기기에 보관한다('저장 대기' 표시). 연결이 돌아오거나 앱을 다시 열면 자동으로 보낸다. 그 사이 날이 지나 서버가 거절하면 버리고 알린다 (R-D2) (2026-10-03 UT)
- **R-S14** 여러 기기: 같은 날을 두 기기에서 열어 두고 칠해도 서로 지우지 않는다. 저장할 때 서버가 '이 기기가 마지막으로 본 상태'와 견주어, 그 사이 다른 기기에서 바뀌었으면 거절하고 새 상태를 불러온다("다른 기기에서 이 날 시간표를 바꿔서 새로 불러왔어요"). 오늘 화면은 창으로 돌아오거나 다시 보일 때, 보이는 동안 1분마다 다시 읽고, 하루 기록은 열 때 새로 읽는다 (2026-10-03 UT 3차)
- **R-S15** 연결 없이 열기: 설치한 앱·브라우저 모두 연결이 없어도 열리고 이 기기에 둔 마지막 내용(계정·할 일·그날 시간표·하루 기록)을 보인다. 그때 칠한 시간은 '저장 대기'로 두었다가 연결되면 저장한다(R-S12, R-S14로 다른 기기와 충돌 확인). 다른 고치기는 "연결이 없어 저장하지 못했어요"로 알린다. 연결이 없으면 화면 맨 위에 작은 '오프라인' 띠 (2026-10-03 UT 4차 기획 결정)
- **R-S16** 그날 기록을 불러오기 전(처음 연 기기에서 느린 연결 등)에는 시간표를 칠하지 않는다 — 안내 "불러오는 중이에요…". 빈 화면에 칠한 것이 서버의 그날 기록을 덮어 지우지 않게. 기기에 둔 내용은 저장할 때마다 함께 고쳐, 다시 열었을 때 방금 칠한 것이 그대로 보이고 바로 칠해도 저장된다 (2026-10-04 칸 칠하기 오류)
- **R-S8** 할 일 목록에 번호(반복 섹션부터 이어서 1, 2, 3…). 실제 블록에는 이름 대신 **번호 동그라미**, 일상 키워드로 칠한 블록은 키워드 첫 글자.
- **R-S9** ⚠️ 알려진 문제: 실제 블록이 계획 블록 중간에서 시작하면 번호가 계획 이름을 가린다. **번호는 구간 오른쪽 끝에 둔다.**
- **R-S10** 앱바 아래 요약: D-day, 오늘의 계획 시간 / 실제 시간. D-day는 **사용자가 계획 › 목표에서 하나 정한다**(이름 + 날짜, 목표 기한에서 골라 채울 수 있음). 정하지 않으면 안 보인다. PC는 목표 설정 화면에서 정하고 사이드바 꿈 카드 위에 보인다 (2026-10-03 기획 결정, 이전: 가장 가까운 목표 기한 자동)

### 4.6 하루 기록
- **R-J1** 화면 하단 "하루 기록" 버튼 → 시트. 버튼에 요약("★4 · 감사 2").
- **R-J2** 시트: 오늘 하루 점수 1~5 → 이유 한 줄 → 감사 세 줄 → 메모.
- **R-J3** 지난 날은 읽기 전용(R-D2).

### 4.7 트래킹 (데스크톱)
주간 / 월간 전환. 위에서 아래로:
- 주간 = 일~토, 월간 = 그 달 1일~말일. 앞뒤 기간으로 이동(이번 기간까지)
1. 계획한 시간 / 실제로 쓴 시간 / 계획 대비 실행(%) — 계획에는 예약 할 일 시간도 들어간다
2. 목표별 계획 대비 실제 — **계획 시간은 할 일과 연결된 계획 블록만 집계.** 키워드만 적은 계획(과 예약 할 일)은 전체 계획에만 포함(안내 문구 표시)
3. 목표별 진척도 — 슬라이더 0~100%(5% 단위), 사용자가 직접 조절, 마지막 수정일 표시. 바꿀 때마다 기록이 남는다. 마무리한 목표는 빠짐
4. 하루 점수 — 달력, 점수를 색 농도로. 날짜 누르면 그날 이유 한 줄. 평균 점수
5. 목표별 누적 시간

- **R-K1** 실제 시간은 실제 블록이 연결된 할 일 → 실천 → 목표로 집계. 일상 키워드 블록은 목표 집계에서 제외, 전체 실제 시간에는 포함.

### 4.8 회고 모음 (데스크톱)
- 마무리한 목표 카드: 인증사진, 목표명, 카테고리 색, 완성/중도 배지, 기간, 누적 시간, 완료한 실천 수, 회고 3칸(적은 것만). 최신순. 필터: 전체 / 완성 / 중도 마무리.

### 4.9 회고 알림 (2026-10-01 기획 결정: M5에서 보냄)
- 매일 정한 시각(계정 관리)에, 그날 **하루 기록을 아직 안 썼으면** 한 번 웹 푸시. 문구: "오늘 하루를 돌아볼 시간이에요 / 시간표를 칠하고 하루 기록을 남겨요."
- 알림 받을 기기: 계정 관리에서 켤 때 그 기기, 휴대폰은 하루 기록을 저장할 때(처음 한 번 허락)·예약 할 일을 추가할 때 등록된다.
