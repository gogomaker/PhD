## 0. 한 문단 요약

PhD는 **목표를 이루기 위한 계획**을 세우는 웹 다이어리다. 잘 만든 종이 스터디 플래너를 웹으로 옮긴 것. 사용자는 데스크톱에서 목표를 세우고 연간 → 월간 → 주간 계획 표로 쪼개 내려오며, 주간 표에 적은 "실천"이 모바일 하루 플래너의 할 일이 된다. 모바일에서는 할 일을 체크하고 10분 단위 시간표를 형광펜처럼 칠해 기록하며, 그 기록이 데스크톱 트래킹으로 다시 올라간다.

**타깃**: 목표를 이루려는 사람. "그냥 오늘 할 일만 적고 싶은" 사용자는 타깃이 아니다. 기능을 넣고 뺄 때 이 기준으로 판단한다.

## 1. 용어 (코드·UI 모두 이 이름으로 통일)

| 용어 | 영문 식별자 | 설명 | 예 |
|---|---|---|---|
| 궁극적 꿈 | `dream` | 한 문장. **선택 사항** | 배운 것을 나누며 사는 연구자 |
| 카테고리 | `category` | 삶의 영역. 7색 중 1색 | 건강, 어학, 일상 |
| ├ 목표 카테고리 | `kind = 'goal'` | 목표를 세우는 영역. 최대 6개 | 어학 |
| └ 일상 카테고리 | `kind = 'daily'` | 목표 없이 생활·시간 기록용. **정확히 1개** | 일상 |
| 일상 키워드 | `daily_keyword` | 일상 카테고리 안의 하위 분류 | 업무, 생활, 이동, 휴식 |
| 되고 싶은 모습 | `category.aspiration` | 카테고리별 한 문장 (유지하는 것이 기획 의도) | 매일 30분, 몸을 움직이는 사람 |
| 목표 | `goal` | 목표 카테고리에 속함. 계획 표의 **열** | 토익 850 |
| 세부목표 | `subgoal` | 목표 아래 단위. 꿈 보드에서 만듦 | 단어, LC, RC |
| 실천 | `practice` | 주간 표에 적는 구체적 행동. 세부목표 1개에 속함 | 매일 단어 40개, LC 교재 2장 |
| 할 일 | `task` | 실천이 하루에 실행된 것, 또는 모바일에서 직접 적은 일 | 10/1의 "매일 단어 40개" |
| 계획 블록 | `time_block (layer=plan)` | 모바일 시간표의 회색 테두리 구간 | 15:00–16:00 치과 |
| 실제 블록 | `time_block (layer=actual)` | 모바일 시간표의 형광펜 구간 | 09:00–10:00 LC |
| 하루 기록 | `day_journal` | 점수(1~5)·이유 한 줄·감사 3줄·메모 | |
| 참고사항 | `note` | 월간·주간 표의 회색 메모 열. 모바일로 내려가지 않음 | 개천절 연휴 |

구조 (기획 중 "나무" 비유: 뿌리=꿈, branch=목표, twig=세부목표, leaf=실천):

```
궁극적 꿈 (선택)
└ 목표 카테고리 (≤6)          + 일상 카테고리 (1) ─ 일상 키워드들
  └ 목표                        └ (목표 없음, 모바일 직접 추가·시간 칠하기 전용)
    └ 세부목표
      └ 실천 (주간 표)
        └ 할 일 (모바일, 하루 단위)
```

## 2. 기술 방향

| 항목 | 결정 | 상태 |
|---|---|---|
| 앱 형태 | **하나의 반응형 웹앱.** 넓은 화면 = 데스크톱 레이아웃(계획), 좁은 화면 = 모바일 하루 플래너 | 확정 |
| 백엔드 | **BaaS 사용** (서버 직접 구현 안 함) | 확정 |
| BaaS 종류 | 데이터가 강하게 관계형(목표→세부목표→실천→할 일)이고, 로그인·파일 저장(인증사진)·행 단위 권한이 필요하므로 **Supabase(Postgres) 권장** | **결정 필요** — 첫 작업 전에 Claude Code가 근거와 함께 제안하고 기획자가 승인 |
| 프레임워크 | Claude Code가 제안 (반응형 + PWA + BaaS 연동이 쉬운 것) | 결정 필요 |
| PWA | 필요. 예약 할 일 **알람(웹 푸시)** 때문 | 확정 |
| 시간대 | 기본 `Asia/Seoul`. 모든 "날짜" 계산은 사용자 시간대 + 하루 시작 시각 기준 | 확정 |

### 2.1 반응형 기준
- 데스크톱 레이아웃: 사이드바 + 본문. 목표 작성·계획 표·트래킹·회고 모음.
- 모바일 레이아웃: 하루 플래너 한 화면. 계획 표 편집 기능은 모바일에 두지 않는다.
- 같은 계정, 같은 데이터. 모바일은 데스크톱 설정(카테고리·목표·실천)을 **읽기만** 하고 만들거나 바꾸지 않는다.

### 2.2 알람 제약 (검수 시 참고)
- 웹 푸시는 PWA 설치가 필요하다. **iPhone은 홈 화면에 추가한 경우에만** 받을 수 있다(iOS 16.4+).
- 기획자는 iPhone이 없으므로 iOS 알람은 직접 검수할 수 없다. Android 크롬 기준으로 검수한다.

## 3. 데이터 모델 (초안)

Claude Code가 BaaS에 맞게 다듬되, **아래 관계와 제약은 유지**한다. 모든 테이블은 `user_id` 기준 행 단위 권한(본인만 읽기·쓰기).

### 3.1 사용자·설정
**profiles**
- `name`, `life_stage` (대학생 / 수험생 / 직장인 / 군 복무 중 / 그 외) — 카테고리 추천에 사용
- `dream` (nullable), `dream_why` (nullable), `dream_day` (nullable)
- `day_start_hour` (4 / 5 / 6, 기본 5) — 하루의 경계
- `week_start` (월 / 일, 기본 월)
- `review_notify_enabled`, `review_notify_time` (기본 22:00)
- `timezone` (기본 Asia/Seoul)

### 3.2 카테고리
**categories**
- `kind`: `goal` | `daily`
- `name`, `color` ∈ {red, orange, yellow, green, blue, purple, pink}
- `aspiration` (되고 싶은 모습, nullable, goal 카테고리만)
- `position`
- 제약: 사용자당 `color` 중복 불가 / `kind='goal'` 최대 6개 / `kind='daily'` 정확히 1개(가입 시 자동 생성, 삭제 불가, 이름·색 변경 가능)
- 목표 카테고리 `color`는 사용자가 고르지 않는다. `position` 순서대로 빨강→주황→노랑→초록→파랑→보라→분홍에서 일상 색을 건너뛰고 자동으로 매긴다(DB 트리거)

**daily_keywords**
- `category_id`(daily), `name`, `position`
- 기본값: 업무, 생활, 이동, 휴식 (추가·삭제 가능)

### 3.3 목표
**goals**
- `category_id` (goal 카테고리만), `name`, `position`
- 특성: `due_month` (필수), `reason`, `importance` (high / mid / low), `fallback` (대안) — reason·importance·fallback은 선택
- `status`: `not_started` | `in_progress` | `completed` | `dropped`
- `started_at` — 이 목표의 실천이 처음 주간 표에 배치된 시각
- 마무리: `finished_at`, `finish_photo_path`(완성일 때만), `retro_achieved`, `retro_regret`, `retro_next`
- `table_position`, `table_hidden` — 계획 표 열 순서·숨김

**subgoals**
- `goal_id`, `name`, `position`

**goal_progress**
- `goal_id`, `percent` (0~100), `updated_at` — 사용자가 트래킹 화면 슬라이더로 직접 매김. 변경 이력 보관 권장

### 3.4 계획 표
**year_cells** — 연간 표
- `goal_id`, `subgoal_id`, `start_month`, `end_month` (병합 범위), `memo`

**month_cells** — 월간 표
- `goal_id`, `subgoal_id`, `year_month`, `start_week`, `end_week` (병합), `comment`

**notes** — 참고사항 열 (월간·주간 공통)
- `scope` (`month` | `week`), `period_key`, `start_index`, `end_index` (병합), `text`

**practices** — 실천 (주간 표)
- `goal_id`, `subgoal_id`, `week_start_date`, `name`
- `kind`: `repeat` | `once`
- `weekdays`: 요일 집합 (1개 이상)
- 표시 위치: 요일이 **1개**면 그 요일 칸, **2개 이상**이면 "이번 주" 줄

### 3.5 하루
**tasks** — 할 일 (하루 인스턴스)
- `date` (사용자 기준 날짜), `source`: `repeat` | `auto` | `picked` | `direct`
- `practice_id` (direct 아니면 필수)
- direct 전용: `name`, `daily_keyword_id`
- 예약: `is_timed`, `start_time`, `end_time`, `alarm`
- `done_at`, `carried_from_date`
- `list_number` 는 저장하지 않고 화면에서 계산 (4.5 참조)

**time_blocks**
- `date`, `layer`: `plan` | `actual`
- `start_slot`, `end_slot` — 0~143 (하루 시작 시각 기준 10분 단위, 끝 포함). **구간 단위로 저장**
- 연결 대상 (하나): `task_id` | `daily_keyword_id` | `label`(자유 키워드, plan만) | 없음(plan의 이름 없는 블록)
- 같은 날·같은 층에서 구간은 겹치지 않는다 (칠할 때 덮어쓰기)

**day_journals**
- `date`, `score` (1~5), `reason` (한 줄), `thanks` (3줄), `memo`

> 할 일을 미리 만들어 둘지(materialize) 그날 열 때 계산할지는 Claude Code가 정한다. 단, **4장의 동작 규칙과 결과가 같아야 한다.**

## 4. 동작 규칙

검수 때 규칙 번호로 지적할 수 있도록 번호를 붙였다.

### 4.1 카테고리·목표
- **R-C1** 목표 카테고리 최대 6개 + 일상 1개 = 최대 7색, 색은 겹치지 않는다. 일상 카테고리 색만 직접 고르고, 목표 카테고리 색은 **순서대로** 정해진다(빨강→주황→노랑→초록→파랑→보라→분홍, 일상 색은 건너뜀). 순서를 바꾸거나 지우면 색도 따라 바뀐다. (2026-10-01 기획 결정)
- **R-C2** 일상 카테고리는 목표 설정·꿈 보드·계획 표에 **나타나지 않는다.**
- **R-C3** 목표는 카테고리 1개에만 속한다. 색은 카테고리 색을 따른다.
- **R-G1** 세부목표는 반드시 목표 1개에 속한다.
- **R-G2** 세부목표가 0개인 목표는 계획 표 열로 추가할 수 없다. (안내: "꿈 보드에서 세부목표를 먼저 추가해 주세요")
- **R-G3** 목표의 "시작" = 그 목표의 실천이 **주간 표에 처음 배치된 시점.** 그때 `not_started → in_progress`.
- **R-G4** `not_started` 목표만 **삭제** 가능. 삭제 시 연간·월간 칸도 함께 지워진다는 확인을 받는다.
- **R-G5** `in_progress` 목표는 삭제 불가, **마무리**만 가능.
- **R-G6** 마무리 종류는 **완성 / 중도 마무리**. 완성일 때만 인증사진 1장. 회고 3칸(해낸 것, 아쉬운 점, 다음에 다르게 할 것). 기간·누적 시간·완료 실천 수는 자동 요약.
- **R-G7** 마무리한 목표는 **다시 열 수 없다.** 같은 일을 다시 하려면 새 목표를 만든다.
- **R-G8** 마무리한 목표는 꿈 보드에서 흐리게 + 배지로 카테고리 맨 아래, 계획 표 열에서는 빠진다. 과거 기록·트래킹 집계는 유지.
- **R-G9** 세부목표 이름을 바꾸면 계획 표의 칩에도 반영된다. 계획 표에 배치된 세부목표는 삭제 불가("계획 표에 배치됨").

### 4.2 계획 표 3종
| 표 | 행 | 칸 내용 | 역할 |
|---|---|---|---|
| 연간 | 월 (12개월) | 세부목표 + 짧은 메모 | 큰 배치 |
| 월간 | 주차 | 세부목표 + 코멘트 | 이번 달 사정에 맞춘 재배분 |
| 주간 | "이번 주" 줄 + 요일 7줄 | 실천 여러 개 | 실제 실천 작성 |

- **R-P1** 모든 표의 열 = 목표. 열 하나는 **항상 세로 한 줄**(열 쪼개기·레인 금지).
- **R-P2** 연간·월간 칸은 병합으로 기간을 표현한다.
- **R-P3** 월간·주간 표 맨 위에 **"상위 계획" 줄**: 월간에는 연간의 이번 달 칸이, 주간에는 월간의 이번 주 칸이 읽기 전용으로 내려온다.
- **R-P4** 월간에서 바꾼 내용은 연간에 **반영되지 않는다.** 연간은 "처음 계획"으로 남는다.
- **R-P5** 월간 칸 팝오버: 그 목표의 세부목표 전체를 보여주되, 연간 표에서 이번 달에 배치한 세부목표를 맨 위에 "이번 달 계획"으로 강조.
- **R-P6** 주간 표에는 **칸 병합이 없다**(참고사항 열 제외). 요일 칸에는 하루짜리 실천만 위아래로 쌓는다.
- **R-P7** 실천 추가 팝오버: 세부목표 선택(상위 계획 줄의 세부목표 강조) → 이름 → 반복/단발(기본 단발) → 요일 칩(복수 선택). 요일 칸을 눌러 열면 그 요일이 미리 선택됨.
- **R-P8** 요일 1개 → 그 요일 칸. 2개 이상 → "이번 주" 줄, 오른쪽에 요일 표시: 연속 "수–금", 떨어짐 "월·수·금", 전체 "매일". 반복 실천은 ↻ 아이콘.
- **R-P9** 칸 안 실천이 3개를 넘으면 "+N개 더"로 접는다.
- **R-P10** 참고사항 열(월간·주간)은 자유 메모. 모바일로 내려가지 않는다.
- **R-P11** 반복이라는 개념은 **실천에만** 있다. 세부목표·목표에는 반복 속성이 없다.

### 4.3 모바일 — 할 일이 생기는 방법
| 섹션 | 출처 | 들어오는 방식 | 못 했을 때 |
|---|---|---|---|
| 반복 | `repeat` | 반복 실천 중 **오늘 요일이 포함된 것**이 자동으로 | 넘어가지 않음(기록에 미완료로 남음) |
| 오늘 할 일 | `auto` | 단발 실천 중 요일이 **오늘 하나뿐인 것**이 자동 배정 | **다음 날로 넘어감** ("어제에서" 표시) |
| 오늘 할 일 | `picked` | 단발 실천 중 요일이 2개 이상인 것을 사용자가 "이번 주에서 담기"로 골라 담음 | 기간 안이면 **다시 담을 후보로 돌아감** |
| 오늘 할 일 | `direct` | 모바일에서 직접 추가 (일상 키워드 선택) | **다음 날로 넘어감** |
| 오늘 할 일 | `direct` + 예약 | 직접 추가 시 "시간 지정" 켬 | **넘어가지 않음** |

- **R-T1** 기간 단발 실천은 기간 안에서 **한 번 완료하면** 이후 후보에서 사라진다.
- **R-T2** "이번 주에서 담기" 목록에는 아직 완료하지 않은, 오늘이 기간에 포함된 기간 단발 실천만 나온다.
- **R-T3** 예약 할 일은 시작·끝 시각을 받고, 시간표 계획 층에 **자동으로 회색 블록**이 생기며(알람 아이콘), 시각에 맞춰 알람.
- **R-T4** 할 일 태그: 목표에서 온 것은 **세부목표 이름**, 직접 추가는 **"일상 · 키워드"**. 색은 카테고리 색.

### 4.4 모바일 — 날짜별 권한 (가장 중요한 원칙: 지난 날은 손댈 수 없다)
| | 오늘 | 내일 | 모레 이후 | 지난 날 |
|---|---|---|---|---|
| 할 일 체크 | O | X | X | X |
| 담기·직접 추가 | O | O | X | X |
| 계획 블록 그리기 | O | O | X | X |
| 실제 칠하기 | O | X | X | X |
| 하루 기록 작성 | O | X | X | X |
| 보기 | O | O | 배정된 실천만 흐리게 | 읽기 전용 |

- **R-D1** "오늘"은 사용자 시간대 + `day_start_hour` 기준. 05시 시작이면 새벽 1시는 아직 전날이다.
- **R-D2** 지난 날 잠금은 **UI만이 아니라 서버(권한 규칙/DB 제약)에서도** 막는다. 이 서비스의 핵심 가치가 "얼마나 성실했는지 정직하게 보이는 것"이기 때문.
- **R-D3** 날짜 이동: 앱바 가운데 날짜 탭 → 달력 / 좌우 화살표 / **앱바 영역에서만** 좌우 스와이프(시간표 드래그와 충돌 방지) / 오늘이 아닐 때 "오늘" 버튼.

### 4.5 모바일 — 10분 시간표
- **R-S1** 한 줄 = 1시간, 6칸 = 10분씩. `day_start_hour`부터 24시간.
- **R-S2** 격자는 얇은 선, 칸 사이 틈 없음. 30분 위치에 점선.
- **R-S3** 두 층:
  - **계획**: 회색 테두리 네모(안은 거의 투명). 이름은 안쪽 왼쪽에 작게. 20분 이하 구간은 이름 생략.
  - **실제**: 카테고리 색 반투명 형광펜 띠(칸 높이 약 70%). 계획 테두리 **아래** 층.
- **R-S4** 블록은 칸이 아니라 **구간**으로 그린다(한 시간 줄 안 연속 구간 = 도형 하나, 여러 줄이면 줄마다 하나, 이름·번호는 첫 줄에만).
- **R-S5** 칠하기는 **형광펜 방식**: 누른 칸부터 현재 칸까지 시간순 구간 전체. 되돌아가면 구간이 줄고 벗어난 칸은 드래그 시작 전 상태로 복원(스냅샷). 거꾸로 긋기 지원. 이미 칠한 칸에서 시작하면 지우기.
- **R-S6** 계획 그리기: 드래그 후 시트에서 **할 일 선택 / 키워드 입력(일상 키워드 칩 제시) / 건너뛰기(이름 없음)**. 블록을 누르면 이름 변경·삭제. 할 일과 연결된 계획은 이름 앞에 카테고리 색 점. 계획 그리기 시 예약 블록 칸은 건너뛴다.
- **R-S7** 실제 칠하기: 할 일 하나 또는 일상 키워드 하나를 브러시로 고르고 칠한다. 다른 것으로 칠해진 칸은 덮어쓴다.
- **R-S8** 할 일 목록에 번호(반복 섹션부터 이어서 1, 2, 3…). 실제 블록에는 이름 대신 **번호 동그라미**, 일상 키워드로 칠한 블록은 키워드 첫 글자.
- **R-S9** ⚠️ 알려진 문제: 실제 블록이 계획 블록 중간에서 시작하면 번호가 계획 이름을 가린다. **번호는 구간 오른쪽 끝에 둔다.**
- **R-S10** 앱바 아래 요약: 가장 가까운 목표 기한 D-day, 오늘의 계획 시간 / 실제 시간.

### 4.6 하루 기록
- **R-J1** 화면 하단 "하루 기록" 버튼 → 시트. 버튼에 요약("★4 · 감사 2").
- **R-J2** 시트: 오늘 하루 점수 1~5 → 이유 한 줄 → 감사 세 줄 → 메모.
- **R-J3** 지난 날은 읽기 전용(R-D2).

### 4.7 트래킹 (데스크톱)
주간 / 월간 전환. 위에서 아래로:
1. 계획한 시간 / 실제로 쓴 시간 / 계획 대비 실행(%)
2. 목표별 계획 대비 실제 — **계획 시간은 할 일과 연결된 계획 블록만 집계.** 키워드만 적은 계획은 전체 계획에만 포함(안내 문구 표시)
3. 목표별 진척도 — 슬라이더 0~100%, 사용자가 직접 조절, 마지막 수정일 표시
4. 하루 점수 — 달력, 점수를 색 농도로. 날짜 누르면 그날 이유 한 줄. 평균 점수
5. 목표별 누적 시간

- **R-K1** 실제 시간은 실제 블록이 연결된 할 일 → 실천 → 목표로 집계. 일상 키워드 블록은 목표 집계에서 제외, 전체 실제 시간에는 포함.

### 4.8 회고 모음 (데스크톱)
- 마무리한 목표 카드: 인증사진, 목표명, 카테고리 색, 완성/중도 배지, 기간, 누적 시간, 회고 3칸. 최신순. 필터: 전체 / 완성 / 중도 마무리.

### 모바일
앱바(날짜 이동) → 요약 줄 → [할 일 영역 | 10분 시간표] 가로 2분할 → 하단 하루 기록 버튼.

- 빈 상태마다 한 줄 안내 + 다음 행동 버튼 하나 (목업 `data="empty"` 참조).

## 7. 개발 순서와 검수 체크리스트

각 단계가 끝나면 Claude Code는 **배포된 미리보기 링크 + 이 체크리스트 결과**를 보고하고, 기획자 검수 후 다음 단계로 간다. 한 단계 안에서도 규칙 번호를 커밋·PR 설명에 적는다.

### M0. 기반
- BaaS·프레임워크 제안 → 승인 → 프로젝트 생성, 배포 파이프라인, 디자인 토큰, 반응형 뼈대
- [ ] 휴대폰과 PC에서 같은 주소로 접속하면 각각 모바일·데스크톱 레이아웃이 뜬다
- [ ] 색·폰트가 목업과 같다

### M1. 계정과 설정
- 가입 4단계, 로그인, 계정 관리, 카테고리(6+1), 일상 키워드
- [ ] 목표 카테고리 7번째는 추가되지 않는다 (R-C1)
- [ ] 같은 색을 두 카테고리에 줄 수 없다 (R-C1)
- [ ] 꿈을 건너뛰고 가입할 수 있고, 사이드바에 "아직 꿈을 적지 않았어요"가 뜬다
- [ ] 하루 시작 시간·한 주 시작 요일을 바꿀 수 있다

### M2. 목표
- 목표 설정, 꿈 보드, 편집 패널, 꿈 작성
- [ ] 일상 카테고리가 목표 설정·꿈 보드에 안 보인다 (R-C2)
- [ ] 패널을 처음 열면 스크롤 없이 목표명·카테고리·기한·세부목표가 보인다
- [ ] 시작 전 목표는 삭제되고, 진행 중 목표는 삭제 버튼 대신 마무리 버튼이 있다 (R-G4, G5)

### M3. 계획 표
- 연간 → 월간 → 주간, 상위 계획 줄, 참고사항, 실천 팝오버
- [ ] 세부목표 없는 목표는 열로 못 올린다 (R-G2)
- [ ] 월간에서 바꿔도 연간은 그대로다 (R-P4)
- [ ] 주간 표에서 어떤 경우에도 열이 쪼개지지 않는다 (R-P1)
- [ ] 요일 칩 1개 → 요일 칸, 여러 개 → 이번 주 줄 + "수–금"/"월·수·금"/"매일" (R-P8)
- [ ] 실천을 처음 배치한 목표가 "진행 중"으로 바뀐다 (R-G3)

### M4. 모바일 하루 플래너
- 할 일 4가지 출처, 담기, 직접 추가·예약, 시간표, 하루 기록, 날짜 이동·권한, 알람(PWA)
- [ ] 주간 표 목요일 칸 실천이 목요일 "오늘 할 일"에 자동으로 있다
- [ ] 반복 실천을 안 해도 다음 날로 안 넘어간다 / 단발·직접 추가는 넘어간다 / 예약은 안 넘어간다 (4.3)
- [ ] 수–금 단발 실천을 수요일에 완료하면 목·금 담기 목록에 안 나온다 (R-T1)
- [ ] 형광펜: 대각선으로 끌어도 사이 칸이 전부 칠해지고, 되돌리면 원래대로 (R-S5)
- [ ] 계획 블록에 이름이 붙고, 짧으면 생략된다 (R-S3, S6)
- [ ] 어제 화면에서 아무것도 바꿀 수 없다 — **새로고침·직접 요청으로도** (R-D2)
- [ ] 모레 화면은 보기만 된다
- [ ] 새벽 1시에 칠한 기록이 전날로 들어간다 (R-D1)
- [ ] Android에서 예약 할 일 알람이 온다

### M5. 기록과 회고
- 트래킹(주간/월간), 진척도 슬라이더, 하루 점수 달력, 목표 마무리 팝업, 회고 모음
- [ ] 키워드만 적은 계획 블록은 목표별 계획 시간에 안 들어간다 (4.7-2)
- [ ] 마무리한 목표는 계획 표 열에서 빠지고, 다시 열 수 없다 (R-G7, G8)
- [ ] 완성일 때만 인증사진 칸이 있다 (R-G6)

### M6. 빈 상태와 마무리 손질
- 모든 화면의 빈 상태, 시작 체크리스트, 스크롤바, 데이터 내보내기
- [ ] 새 계정으로 처음부터 끝까지(목표 → 주간 실천 → 모바일 기록 → 트래킹) 막힘 없이 갈 수 있다

- 데이터 내보내기 형식 세부
